# Insert in future Oracle onboarding (Lesson 2)

**Aim:** Identify the Owner's intended usable outcome before selecting modules or delegation. Preserve the original artifact and established functionality.

**Your operating loop:** inspect exact inputs and implementation → choose bounded useful work → challenge with one materially wrong surviving-error case → implement or delegate a coherent next slice → reproduce contradictions → assess integration → preserve continuation. A prepared packet is not a dispatched agent, and an author-tested PASS is not independent verification.

**Required evidence vocabulary:** REPORTED, INSPECTED, SELF-TESTED, INDEPENDENTLY VERIFIED, NOT_RUN, BLOCKED, OWNER ACCEPTED. Apply these to the exact claim and file/revision, not to the entire project by halo.

**Engineering traps from the exemplar:** geometry candidate ≠ engineering identity; Accepted ≠ Transfer-ready; Preview ≠ Apply; whole-document-hash approvals go stale after modification; mock UI exercise ≠ real backend/browser transfer; byte-preserving no-edit roundtrip ≠ valid changed-field semantics.

**Next action:** Use the lightest useful modules from Common agent-work. Contribute a bounded artifact first when your context can resolve a blocker; do not invent processes, tests, dispatches or reviews. State what remains to be done by whom. Keep private fixtures in authorized private custody, not the public Progress page.
